# Stamina Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stamina as in Tales of Honor: a max and a current value per character, `:c maxstamina/stamina/spend/recover`,
and a green stamina bar under the HP bar on the HP panel.

**Architecture:**
- **Reuse the HP work:**
  - current HP (spec `docs/superpowers/specs/2026-11-25-hp-panel-design.md`, already on main);
  - `hp_clamp`, `hp_after_max_change` and `hp_bar_layout` work for any "max down to −max" value.
- **Ops:** a new op `OP_SET_STAMINA` with modes set, change and spend. Spend is refused below 0, and the host
  checks it, so two people spending at the same time can't get past it. Max stamina is a new `STAT_MAXSTAMINA`
  bit in `OP_SET_STATS`.
- **Formats:** save format v6, protocol 6.

**Tech Stack:** C11, SDL3, Vulkan 2D API (`src/draw.h`), ImageMagick e2e scripts.

Spec: `docs/superpowers/specs/2026-11-25-stamina-design.md`.

**Conventions:**
- `make test` runs five test programs, each printing `N checks, 0 failed`.
- `make` must build without warnings (`make 2>&1 | grep -i warn`).
- The e2e tests (`./tests/e2e_net.sh`, `TOH_E2E_RELAY=1 ./tests/e2e_net.sh`, `./tests/e2e_save.sh`) need a display
  and `make build/toh-relay`.
- The tiling window manager may resize test windows. A rare e2e failure with a very short client window is that,
  not a bug; rerun.
- Commit messages are plain sentences ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Docs rule (CLAUDE.md):** the guides only describe what is in the game, with no "coming soon" notes. They
  change in Task 6 together with the e2e-verified feature.

```c
static void apply_stamina(const Op *op) {
    for (int i = 0; i < op->ids.count; i++) {
        Entity *e = character_at(op, i);
        if (!e) continue;
        int before = e->stamina;
        long long v = op->healthMode == HEALTH_SET    ? op->value
                    : op->healthMode == STAMINA_SPEND ? (long long)e->stamina - op->value
                                                      : (long long)e->stamina + op->value;
        e->stamina = hp_clamp(v, e->maxStamina);
        if (op->remote) continue;
        char name[CHAR_NAME_MAX + 16];
        entity_display_name(e, name, sizeof(name));
        console_log("%s: stamina %d/%d -> %d/%d%s", name, before, e->maxStamina, e->stamina, e->maxStamina,
                    e->stamina <= 0 ? " (exhausted)" : "");
    }
}
```

Note that the spend check only works because `ops_check` runs right before `ops_apply` on the host (and on the
clients, against the same state). That is how every op works here.
